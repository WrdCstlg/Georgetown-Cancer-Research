# AfriCAN DANCE — Risk Register, Second-Order Failure Modes, and Coding-Agent Control
### Companion to the Build Plan · v0.1

Three parts: (1) the first-order critiques, documented with the remediation now in place and its early-warning signal; (2) the failures that remain *after* those remediations — including the ones the remediations themselves introduce; (3) how to stop the coding agent from hallucinating either the build or the intent.

The through-line, stated once: almost none of these are the code breaking. They are the system being **confidently wrong** or **beside the point**. The authoritative layer that matters here is not the graph — it is biological validity, reviewer trust, and her team running it without you. Every control below exists to keep the fast probabilistic layer (models, and the coding agent itself) gated behind a slow verifiable one.

## Part 1 — First-order critiques (documented, remediated)

| # | Failure | Remediation in place | Early-warning signal |
|---|---------|----------------------|----------------------|
| R1 | **Bias laundering.** European-calibrated tools (AlphaMissense, EVE, GDSC/CCLE models, ClinVar/COSMIC labels) reproduce the bias the study exists to remove — now dressed as "AI-validated." | Every tool benchmarked against African-ancestry ground truth before it is trusted; reclassifications carry a calibration-status flag, not just a score. | Reclassification rates for AA/Ghanaian/Ethiopian tracking European rates; tool confidence uncorrelated with ancestry proportion. |
| R2 | **Pre-screen steers the wet lab away from the signal.** European-trained triage deprioritizes exactly the ancestry-specific responses that are the discovery. | Pre-screen may only *add* PDO-drug combinations to the screen, never subtract; full grant screen runs regardless. | Pre-screen ranking anti-correlated with where ancestry-stratified signal later appears. |
| R3 | **Geneticizing a structural disparity.** Ancestry treated as a genetic variable when the disparity is also SES / environment (diet, aflatoxin, access). | SES and environmental confounders measured and entered as covariates; causal claims conditioned on them, not on ancestry alone. | Ancestry effects that vanish when SES/collection-site enters the model. |
| R4 | **Small-N phantom signals + leakage.** Bespoke models overfit; training on organoid data then "validating" on organoids is circular. | Whole organoid *lines* held out; external validation required before any claim; effect sizes reported with out-of-sample intervals. | In-sample strength that collapses on held-out lines or TCGA. |
| R5 | **AI eats grant credibility before funding.** Study sections read AI-central framing as over-ambition. | Grant frames AI as surgical upgrades to already-named methods; biology in front; novel systems positioned as de-risked upside. | Reviewer language about scope/feasibility rather than significance. |
| R6 | **Platform outlives its operator.** A system only the builders can run is an orphaned dependency, not the shared asset the vision promises. | Built on her team's stack (R, a Postgres they can run); runbooks and handover; black-box components isolated behind stable interfaces. | Any task that only Senan/Qiwu/one ML engineer can execute. |
| R7 | **Distillation layer nobody opens.** A power-user interface for a user who doesn't exist on her team is shelfware. | Interface designed against her team's actual workflow (R, spreadsheets); adoption measured, not assumed. | Query layer usage near zero after week two. |
| R8 | **Scope overshoot.** The grand build eats the deadline while the VUS problem she actually needs slips. | Phase-2 VUS win shipped first, on existing 150-tumor data, before anything ambitious. | Substrate work in flight while the submission date nears with no shippable result. |

## Part 2 — Anticipated second-order failure modes

Assume Part 1 is handled. The next layer is where remediations trade one failure for a subtler one, and where deeper problems only become visible once the obvious ones are gone. Ordered roughly by how quietly they kill the vision.

**S1 · "African ancestry" is not one calibration target.** The R1 fix — calibrate to African-ancestry ground truth — reintroduces a coarser version of the same error, because Ghanaian (West African), Ethiopian (East African, substantial Eurasian admixture), and African American (admixed, ~20–25% European) are genetically distinct, and the grant's own data says so. A tool de-biased on AA data can be miscalibrated for Ethiopians. *Guard:* calibrate and report per-population, not to a monolithic "African" target; treat within-African heterogeneity as first-class, which the continuous-AFR design already supports if you actually use it.

**S2 · Continuous ancestry vs. a clinic that decides in binaries.** The R3/methodology fix — ancestry continuous everywhere — is correct for inference and unusable at the point of care. Trials and treatment decisions are yes/no; the clinic holds self-reported race, a noisy proxy for the continuous measure. The grant's own endpoint ("biomarker-stratified trials regardless of self-reported ancestry") requires collapsing the continuum back into a decision. *Guard:* design the continuous→discrete translation deliberately, as its own validated step, rather than letting it happen ad hoc downstream — and be explicit that the rigorous internal model and the deployable biomarker are two different objects.

**S3 · CRISPR ground truth answers a narrower question than the claim.** Elevating causal ML validated against CRISPR isogenics is right, but isogenic knock-in validates *one variant's effect in a controlled organoid background* — not that the variant causes differential response *in patients*, in the full genetic and environmental context. And organoids have no immune/microenvironment, so any MSI/checkpoint-immunotherapy causal claim cannot be validated in PDOs at all. Overreading clean isogenic confirmation as validating the epidemiological or clinical claim is an inferential error the provenance layer will happily certify. *Guard:* label each causal claim with the exact question its ground truth answers; never let organoid validation stand in for a clinical causal claim; flag immunotherapy-relevant claims as PDO-unvalidatable by construction.

**S4 · Provenance becomes rigor theater.** The traceable, cited, query-backed answer raises confidence in whatever it returns — including a laundered-bias result. The trust infrastructure amplifies the cost of being wrong. *Guard:* provenance must surface **calibration status and known limitations as prominently as the result**, not just data lineage; an answer whose producer is out-of-calibration for the queried population must render with that caveat attached, not as a clean number.

**S5 · The query layer confabulates at the semantic layer, not the SQL layer.** Constraining the LLM to schema-validated text-to-SQL stops fabricated tables; it does not stop the agent generating *valid SQL for a subtly wrong question* — wrong strata joined, "enriched" answered without "and druggable and survival-linked." Syntactically grounded, semantically wrong, and harder to catch because real numbers came back. *Guard:* the query layer must echo its interpretation of the question in structured form for confirmation before executing, and expose the exact query and strata it used; treat semantic misread as the primary failure mode, not SQL validity.

**S6 · Sustainability and sophistication pull apart.** The R6 fix (make it maintainable by an R-and-spreadsheets team) directly collides with the innovations that justify the methods papers (GNN, custom predictor, causal ML), which are *not* maintainable in that world. You can have transferable or cutting-edge per component, not both by default. *Guard:* draw the line explicitly, component by component — which capabilities are permanent assets the team owns, and which are researcher-operated instruments that will go dark when the engagement ends — and make that a stated decision, not a discovered surprise.

**S7 · The grant framing under-scopes the real build.** The R5/R8 fix splits the modest reviewer story from the substrate build story. If reviewers fund the modest version and the team builds the substantial one, budget, effort, and timeline diverge from the award, and progress reports must reconcile a promise/delivery gap. *Guard:* keep the build phased so the funded-and-promised layer (surgical AI upgrades) is genuinely shippable on its own, and the substrate is explicitly your owned infrastructure (D1) rather than an unfunded grant obligation.

**S8 · The unique dataset is an un-validatable dataset.** The custom predictor's selling point — the only matched AA CRC multi-modal dataset in the world — is also why it has no external validation set: you cannot replicate an ancestry-aware CRC classifier against another ancestry-aware CRC cohort, because none exists. Uniqueness is simultaneously the publishability and the validation gap, and methods reviewers will press exactly there. *Guard:* pre-register the validation strategy (held-out lines, orthogonal assays, prospective checks as African specimens accrue) and lead the methods paper with that, rather than with novelty; treat "unique" as a liability to be managed, not only a claim to be made.

**S9 · The binding constraint is the specimen pipeline, not the system.** African specimens accrue over time, the organoid biobank does not yet exist, RNA-seq is future. Large parts of the system have nothing to run on for a long while, and when real multi-site data arrives it brings FFPE quality variance, three-continent batch effects, and collection-site confounding that assumptions built against clean data will not survive. The system can be "done" and idle, then wrong when data lands. *Guard:* validate against the messiest real preliminary data you have, not synthetic ideals; keep the build gated on data availability (Phase 5 does not start until organoids exist); assume the correctness you proved on prelim data must be re-proven on the real multi-site set.

**S10 · A confirmation engine for the expected story.** Built to find MYC/WNT/PI3K-enriched, KRAS-driven, ancestry-specific targets — the preliminary frame from an n=77, underpowered RNA-seq pilot — the system can become a machine that surfaces evidence for the expected story and is blind to the disconfirming one (weaker-than-expected ancestry effect, or a dominant SES/environmental signature). Disconfirmation is the scientifically more valuable outcome, and a distillation layer optimized for the expected insight can suppress it. *Guard:* build the null and the alternative in explicitly — the pipeline must be able to *report* "the ancestry effect is smaller than the pilot suggested" as a first-class result, and pre-registration protects against retrofitting the frame.

**S11 · The human layer diverges from the technical one.** Orthogonal to any code and the most likely actual killer: authorship and credit (who leads the methods paper vs. the biology paper), IP friction if the owned substrate (D1) meets the institution's grant terms, and attribution when the AI produces the key finding. A collaboration can succeed technically and end on credit. *Guard:* settle authorship norms, IP boundaries, and contribution attribution in writing *before* results exist, when they are still abstract and easy to agree on.

## Part 3 — Forcing the coding agent not to hallucinate the build or the intent

The coding agent is a fast probabilistic producer. Prompting does not prevent hallucination; it is *contained* by making unverified output unable to pass a gate — the same fast/slow discipline, turned on the tooling. Two failure classes: fabricating the **build** (code, APIs, architecture, "it works") and drifting from the **intent** (the spec, and behind it, the professor's actual goals). Controls for each, then where to concentrate them.

### Ground the build — against fabricated code and architecture

- **G1 · Retrieve before edit.** The agent must quote the actual current file, signature, or interface it is about to change before proposing a change — your read-only forensic pattern ("report verbatim and stop"). No edit is accepted to code the agent has not first demonstrated it has read. This kills the most common fabrication: editing an interface the agent imagined.
- **G2 · Closed-world dependencies.** Pin everything with lockfiles. The agent must cite the real function signature from installed source, not from memory, and every symbol it uses is existence-checked by a type-checker/linter in CI. Invented APIs then fail mechanically instead of shipping — the machine, not the reviewer, catches the confabulated call.
- **G3 · Execution is the arbiter, never the agent's narration.** "This works" is not evidence; a pasted run, a passing test, a type-check are. No passing execution artifact → the change is **SPECIFIED, not FUNCTIONAL**, and cannot be marked done. Your maturity ladder becomes the merge gate.
- **G4 · Golden fixtures for scientific correctness.** Numeric and biological correctness cannot be eyeballed — this is where a coding agent silently drifts most dangerously in a genomics pipeline. Pin known-input → known-output fixtures: the 150-tumor preliminary data → its expected VUS-reduction and driver calls, plus small hand-checked toy cases. Any logic change that alters a fixture output fails loudly and must be justified. A hallucinated transformation that "looks reasonable" cannot survive a fixture.
- **G5 · Bounded diffs, priced blast radius.** One change at a time, blast radius stated before authorizing, reviewed against the actual pre-state. Fabrication hides in large multi-file generative rewrites; forbid them. Small diffs keep the hallucination surface reviewable.
- **G6 · Concentrate the strongest controls on the novel components.** The agent confabulates most where its priors are thinnest — the GNN on this specific interaction graph, the custom multi-modal predictor, the causal layer — which is exactly where correctness is hardest to verify. Boilerplate can run lighter; the novel science gets fixtures, execution evidence, and expert-pinned criteria without exception.

### Ground the intent — against drift from spec and from her goals

- **I1 · Restate and halt.** Before writing code, the agent echoes its understanding of the task and the acceptance criteria in its own words and stops for confirmation. Divergence between the echo and the spec is caught before code exists, when it is free to fix.
- **I2 · Acceptance criteria are executable, not prose.** Prose intent ("distill insights," "ancestry-enriched") is decomposed into checks the agent cannot satisfy by narration; "done" is the check passing. Any ambiguity left in prose is ambiguity the agent will fill with its own interpretation — decompose it first or expect drift (this is S5 at the code level).
- **I3 · Domain intent is human-owned and fixed.** The agent never infers biological or clinical meaning. What counts as "ancestry-enriched," "actionable," or a significance threshold is defined by Senan/Qiwu/Dr. Laura and handed to the agent as fixed criteria. The agent implements definitions; it does not author them. This is the firewall between a coding agent and the professor's actual intent, which it cannot access.
- **I4 · Surface at forks, never assume.** When the agent hits a decision the spec does not cover, it logs a decision record and stops, rather than silently picking. Ban the buried "I assumed X" inside a diff — an unlogged assumption is a rejected change.
- **I5 · Adversarial review — measurement separated from mutation, applied to intent.** A second pass (a separate agent instance or a dedicated review prompt) whose only job is to find where the implementation diverges from the spec. The builder does not grade its own homework.
- **I6 · Traceability chain: code → spec → aim → her goal.** Every module maps to a spec item, every spec item to an aim, every aim to a stated objective of the R01. Orphan code (no spec parent) and orphan specs (no goal parent) are both red flags — the first is scope creep, the second is intent drift — and both should fail review.

### The meta-principle

The agent is the probabilistic layer; the gates above are the authoritative one. You are not trying to make the model reliable — you are making its unreliable output unable to reach `main` without passing checks that a hallucination structurally cannot pass: a symbol that does not exist fails the type-checker, a wrong transformation fails a fixture, a misread intent fails an executable acceptance criterion, a silent fork fails review. That is the same architecture this whole system is built on, pointed at the thing building it.
